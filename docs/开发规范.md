# 开发规范

> 这份文件是硬规矩，不是建议。写代码、提交、改表之前先看一眼。
> 定这份规矩的目的只有一个：**半年后你自己还看得懂，别人接手能跑起来。**

## 1. 目录与分层

```
cn.edu.cust.assoc
├─ controller    只做参数接收、调用 service、返回视图/JSON
├─ service       业务逻辑，事务边界在这一层
├─ repository    数据访问，只写查询
├─ domain        实体与枚举
├─ dto           对外传输对象
├─ config        配置类
└─ common        统一返回、异常、工具
```

- controller 里**不写业务判断**，service 里**不碰 HttpServletRequest**。
- 实体（Entity）**绝不直接交给模板或接口**，一律转 DTO。

## 2. 命名

| 对象 | 规则 | 例 |
|---|---|---|
| 类 | PascalCase | PointLedgerService |
| 方法 / 变量 | camelCase | calculatePoints |
| 常量 | UPPER_SNAKE | MAX_POINTS_PER_VULN |
| 表 / 字段 | snake_case | points_ledger / occurred_on |
| DTO | 后缀 Dto | ArticleDto |
| 枚举 | UPPER_SNAKE | SUPER_ADMIN |

## 3. 方法大小

- 一个方法不超过 **40 行**，controller 方法不超过 **15 行**。
- 超过就先拆，别用注释分段硬扛。

## 4. 参数校验

- 入参用 Bean Validation（`@Valid` + `@NotBlank` / `@Size` / `@Min`），**不在 service 里手写一串 if**。
- 前端校验只是体验，**服务端必须再校验一次**。

## 5. 异常与日志

- 业务异常统一 `BizException(code, message)`，由全局异常处理器转成页面或 JSON。
- **不吞异常**：catch 之后要么处理，要么带上原文重新抛。
- 日志用占位符 `log.info("审核通过 id={}", id)`，**不要字符串拼接**。
- **禁止**在日志里打印密码、Token、完整手机号。

## 6. SQL 与数据

- 表结构**只由 Flyway 管理**，JPA 用 `ddl-auto=validate`。
- 禁止字符串拼接 SQL，全部走参数绑定。
- 写操作加 `@Transactional`；跨表写必须在同一个事务里；**不在事务里做远程调用**。
- 时间字段统一 `Asia/Shanghai`；积分用 `int`，不用浮点。

## 7. 三条不可违反的红线

1. 积分流水**只增不改**，撤销靠反向流水。
2. 每笔流水必须有**幂等键**，唯一约束兜底。
3. **未审核的媒体文件**不进公共目录，访问必须过鉴权。

## 8. Git

- 分支：`main` 只放能跑的版本；开发开功能分支 `feat/xxx`、修 bug 用 `fix/xxx`。
- 提交信息格式：`<type>: <一句话>`，type 取 `feat / fix / chore / docs / refactor / test`。
- **一次提交只做一件事**，提交前先 `mvn -q test`，绿了再提交。
- 密码、密钥、本地配置一律不进仓库。

## 9. 测试

- 每个 service 至少 **1 个正常用例 + 1 个边界用例**。
- 改积分、权限、媒体访问这三块，**必须**补测试 —— 它们的错不会当场报错，只会慢慢算错。

## 10. 注释

- 注释写**为什么**，不写**是什么**。
- 中文注释；公共方法写清入参含义和异常情况。

---

违反上面任何一条，都在 code review 里打回。规矩是给未来的自己定的。
