# 运维手册

> 目标是：**第二个人照着这份文档，不问人也能发一次版、恢复一次数据。**

## 1. 目录约定

```
/opt/xyx/
  releases/20261028-1530/app.jar   每次发布一个目录
  current -> releases/...          符号链接，切换靠它
  config/application-prod.yml      含数据库密码，权限 600
/srv/xyx/public/                   审核通过的公开文件
/srv/xyx/private/                  未审核文件（不进 Nginx 目录）
/var/backup/                       每日备份
/var/log/xyx/                      应用日志与 GC 日志
```

## 2. 发布

1. 本地构建：`mvn clean package`，得到 `target/cust-ctf-assoc-*.jar`。
2. 生成校验值：`sha256sum cust-ctf-assoc-*.jar > 同名.sha256`。
3. 上传到服务器 `/tmp`。
4. 执行 `./deploy.sh /tmp/xxx.jar`（首次先 `chmod +x`）。

脚本做的事：校验 → 备份库 → 切链接 → 重启 → 探活 30 次 → 失败自动切回上一个版本。

**生产机上永远不跑 Maven**：2 核 4G 的机器边编译边跑服务，构建自己就会因为内存不足失败。

## 3. 备份与恢复

每天 03:00 由 cron 跑 `backup-db.sh`：mysqldump + 上传目录 → 打包 → AES 加密 → 本地留 7 天 → 同步异地。
加密口令放 `/etc/xyx/backup.pass`，**不进仓库、不进备份包**。

恢复：

```bash
openssl enc -d -aes-256-cbc -pbkdf2 -pass file:/etc/xyx/backup.pass \
  -in assoc-20261028.tar.gz.enc | tar -xz -C /tmp/restore
mysql -u root -p assoc_dev < /tmp/restore/assoc_dev.sql
tar -xf /tmp/restore/uploads.tar -C /srv/xyx
```

**每季度真做一次**：在干净机器上起应用，验证登录、积分求和、图片访问、审核状态四件事。没演练过的备份不算备份。

## 4. 日常检查

| 看什么 | 怎么看 |
|---|---|
| 服务活着 | `systemctl status xyx` |
| 健康检查 | `curl 127.0.0.1:8080/actuator/health` |
| 磁盘 | `df -h`，到 70% 就处理 |
| 内存 | `free -m`，available 长期低于 300M 要查 |
| 日志 | `journalctl -u xyx -n 200` |

## 5. 常见故障

**应用起不来**：先看 `journalctl -u xyx -n 100`。Flyway 校验失败说明迁移脚本被改过 —— 不要改历史脚本，新建 V8、V9。

**端口被占**：`ss -lntp | grep 8080`。

**图片打不开**：确认 `media.zone` 是 PUBLIC、文件在 `/srv/xyx/public`、`/media/{id}` 返回 200。
