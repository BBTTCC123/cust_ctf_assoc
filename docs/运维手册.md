# 运维手册

> 目标是：**第二个人照着这份文档，不问人也能发一次版、恢复一次数据。**

## 1. 目录约定

```
/opt/xyx/
  releases/20261028-1530/app.jar   每次发布一个目录
  current -> releases/...          符号链接，切换靠它
/etc/xyx/
  xyx.env                          应用环境变量（含数据库密码），权限 600
  my.cnf                           备份账号的 MySQL 客户端配置，权限 600
  backup.pass                      备份加密口令，权限 600
  backup.env                       异地复制目标 OFFSITE_REMOTE，权限 600
/srv/xyx/public/                   审核通过的公开文件
/srv/xyx/private/                  未审核文件（不进 Nginx 目录）
/var/backup/                       每日备份（本地 7 天）
/var/log/xyx/                      应用日志与备份日志
```

**权限检查**（每月一次）：`ls -l /etc/xyx` 里三个文件都应该是 `-rw-------`，目录 `drwx------`。

## 2. 发布

1. 本地构建：`mvn clean package`，得到 `target/cust-ctf-assoc-*.jar`。
2. 生成校验值：`sha256sum cust-ctf-assoc-*.jar > 同名.sha256`。
3. 上传到服务器 `/tmp`。
4. 执行 `./deploy.sh /tmp/xxx.jar`（首次先 `chmod +x`）。

脚本做的事：**先按 app.jar 的实际哈希校验上传文件** → 备份数据库（备份失败即中止）→ 切链接 → 重启 → 探活 30 次 → 失败自动切回上一个版本。

**生产机上永远不跑 Maven**：2 核 4G 的机器边编译边跑服务，构建自己就会因为内存不足失败。

### 迁移兼容性

- 迁移只加表/列/索引，不删不改；新列必须可空或有默认值，旧 JAR 才能继续跑。
- 需要破坏性变更时，分两次发布：第一次只加新列新表并双写，第二次才删旧结构。
- 发布前看一遍新迁移文件；不确定就先在测试库跑一遍再回滚演练。

## 3. 备份与恢复

每天 03:00 由 cron 跑 `backup-db.sh`：mysqldump + 上传目录 → 打包 → AES 加密 → 本地留 7 天 → 复制到对象存储。

备份脚本依赖：

- `/etc/xyx/my.cnf`：最小权限备份账号（SELECT / SHOW VIEW / TRIGGER / LOCK TABLES），chmod 600；
- `/etc/xyx/backup.pass`：加密口令，chmod 600；
- `OFFSITE_REMOTE`：rclone 目标，不配置时脚本以退出码 2 结束并明确报警（本地备份仍然成功）。

对象存储必须开启**版本控制**，并设置生命周期（如 90 天）。只在本机留 7 天的备份不算异地备份。

恢复：

```bash
openssl enc -d -aes-256-cbc -pbkdf2 -pass file:/etc/xyx/backup.pass \
  -in assoc-20261028-030001.tar.gz.enc | tar -xz -C /tmp/restore
mysql -u root -p assoc_dev < /tmp/restore/assoc_dev.sql
tar -xf /tmp/restore/uploads.tar -C /srv/xyx
```

**每季度真做一次**：在干净机器上起应用，验证登录、积分求和、图片访问、审核状态四件事。没演练过的备份不算备份。演练记录：

| 日期 | 执行人 | 恢复来源（本地/对象存储） | 数据库 | 上传目录 | 登录 | 积分 | 图片 | 审核 | 备注 |

## 4. 日常检查

| 看什么 | 怎么看 |
|---|---|
| 服务活着 | `systemctl status xyx` |
| 健康检查 | `curl 127.0.0.1:8080/actuator/health`（actuator 只允许本机/内网） |
| 磁盘 | `df -h`，到 70% 就处理 |
| 内存 | `free -m`，available 长期低于 300M 要查 |
| 日志 | `journalctl -u xyx -n 200` |
| 备份 | `tail -50 /var/log/xyx/backup.log`，确认没有“未设置 OFFSITE_REMOTE”告警 |
| 审计 | 后台「审计日志」按时间/操作人查敏感操作 |

## 5. 常见故障

**应用起不来**：先看 `journalctl -u xyx -n 100`。Flyway 校验失败说明迁移脚本被改过 —— 不要改历史脚本，新建 V9、V10。

**提示 ADMIN_PASSWORD 不符合安全要求**：换 12 位以上、含大小写/数字/符号三类的密码；只需在第一次创建超管时设置，账号已存在时不会重新校验。

**端口被占**：`ss -lntp | grep 8080`。

**图片打不开**：确认 `media.review_state=APPROVED`、`media.zone=PUBLIC`、可见范围与访问者身份匹配（PUBLIC 所有人 / MEMBER 登录成员 / OWNER 仅上传人）、文件在 `/srv/xyx/public`、`/media/{id}` 返回 200。

**用户被禁用后还能操作**：确认是新版本（会撤销会话）；旧会话下一次请求应被踢回登录页。

**备份脚本报错**：先看日志第一行，按提示补 `/etc/xyx/my.cnf` 或 `backup.pass`；再手动执行一次 `mysql --defaults-extra-file=/etc/xyx/my.cnf -e 'SELECT 1'` 验证账号。

## 6. 回滚流程

1. `systemctl stop xyx`。
2. `ln -sfn /opt/xyx/releases/<上一个版本> /opt/xyx/current`。
3. `systemctl start xyx`，`curl 127.0.0.1:8080/actuator/health` 确认 UP。
4. 如果新版本迁移与旧 JAR 不兼容：停止应用 → 用发布前自动备份恢复数据库 → 再启动旧版本。
5. 记录回滚原因、时间、版本号。
