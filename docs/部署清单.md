# 部署清单（服务器到手后照这个走）

> 前提：一台 2 核 4G / Ubuntu 22.04 的云服务器，一个已备案的域名。
> 每一步都有「验收」，不通过就别进下一步。

## 0. 先确认三件事

- [ ] 域名已备案（没备案的话 80/443 会被云厂商拦，只能内测）
- [ ] 服务器能 SSH 登录，你是 root 或有 sudo
- [ ] 本地 `mvn clean package` 能打出 jar

## 1. 系统初始化（约 20 分钟）

```bash
# 建一个专用账号，别用 root 跑应用
adduser --system --group --home /opt/xyx xyx

# 更新
apt update && apt upgrade -y

# 时区
timedatectl set-timezone Asia/Shanghai

# 防火墙：只开 22/80/443；8080 不对公网开放
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable

# 防爆破
apt install -y fail2ban
```

**验收**：`ufw status` 只看到 22/80/443；`date` 显示 CST。

## 2. 装运行环境

```bash
apt install -y openjdk-21-jre-headless mysql-server nginx rclone
mysql_secure_installation
```

MySQL 只监听本机：`/etc/mysql/mysql.conf.d/mysqld.cnf` 里 `bind-address = 127.0.0.1`。

建库建账号：

```sql
CREATE DATABASE assoc_dev CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'assoc_app'@'127.0.0.1' IDENTIFIED BY '强密码';
GRANT ALL PRIVILEGES ON assoc_dev.* TO 'assoc_app'@'127.0.0.1';

-- 备份用的最小权限账号（只需要读和锁表）
CREATE USER 'assoc_backup'@'127.0.0.1' IDENTIFIED BY '另一个强密码';
GRANT SELECT, SHOW VIEW, TRIGGER, LOCK TABLES ON assoc_dev.* TO 'assoc_backup'@'127.0.0.1';
FLUSH PRIVILEGES;
```

**验收**：`mysql -u assoc_app -p -h 127.0.0.1 assoc_dev -e 'select 1'` 能通。

### 2.1 创建备份用的客户端配置

`/etc/xyx/my.cnf`（权限 600，只有 root 可读）：

```ini
[client]
host=127.0.0.1
port=3306
user=assoc_backup
password=另一个强密码
default-character-set=utf8mb4
```

```bash
mkdir -p /etc/xyx
chmod 700 /etc/xyx
vi /etc/xyx/my.cnf
chmod 600 /etc/xyx/my.cnf
chown root:root /etc/xyx/my.cnf
```

**验收**：`mysql --defaults-extra-file=/etc/xyx/my.cnf -e 'SELECT 1'` 能通；`ls -l /etc/xyx/my.cnf` 是 `-rw-------`。

## 3. 部署应用

```bash
mkdir -p /opt/xyx/releases /var/log/xyx /srv/xyx/public /srv/xyx/private
chown -R xyx:xyx /opt/xyx /var/log/xyx /srv/xyx

# 上传 jar（本地打好包、带 .sha256）
scp target/cust-ctf-assoc-*.jar* root@服务器:/tmp/
```

### 3.1 环境变量文件（不要写进 systemd unit）

`/etc/xyx/xyx.env`（权限 600）：

```ini
DB_URL=jdbc:mysql://127.0.0.1:3306/assoc_dev?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false
DB_USER=assoc_app
DB_PASSWORD=数据库强密码
ADMIN_USERNAME=Yorkchain
ADMIN_PASSWORD=首次启动用的一次性强密码
STORAGE_ROOT=/srv/xyx
```

```bash
vi /etc/xyx/xyx.env
chmod 600 /etc/xyx/xyx.env
chown root:root /etc/xyx/xyx.env
```

`ADMIN_PASSWORD` 至少 12 位，包含大小写、数字、符号中的三类；缺省、默认值或弱口令会让应用**拒绝启动**。
第一次登录后系统会强制改密，改完这个一次性密码就作废。

`/etc/systemd/system/xyx.service`：

```ini
[Unit]
Description=cust-ctf-assoc
After=network.target mysql.service

[Service]
User=xyx
WorkingDirectory=/opt/xyx/current
EnvironmentFile=/etc/xyx/xyx.env
ExecStart=/usr/bin/java -Xms512m -Xmx768m -XX:MaxMetaspaceSize=192m \
  -XX:+UseG1GC -Duser.timezone=Asia/Shanghai -jar /opt/xyx/current/app.jar
Restart=always
RestartSec=5
MemoryMax=1536M

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now xyx
```

**验收**：`curl 127.0.0.1:8080/actuator/health` 返回 `{"status":"UP"}`；`systemctl status xyx` 是 running；`ps -ef | grep java` 看不到明文密码。

## 4. Nginx + HTTPS

`/etc/nginx/sites-available/xyx`：

```nginx
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    client_max_body_size 20m;
    add_header X-Frame-Options DENY always;
    add_header X-Content-Type-Options nosniff always;
    add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'" always;

    # 健康检查只给本机/运维用，公网一律拒绝
    location /actuator {
        deny all;
        return 404;
    }

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        # 覆盖而不是追加：客户端伪造的 X-Forwarded-For 会被丢掉
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 10s;
        proxy_read_timeout 60s;
    }
}
```

```bash
ln -s /etc/nginx/sites-available/xyx /etc/nginx/sites-enabled/
certbot --nginx -d your-domain.com
systemctl reload nginx
```

**验收**：浏览器打开 `https://your-domain.com` 能看到首页，地址栏是锁；`curl -I https://your-domain.com/actuator/health` 返回 404；从外网访问 `http://服务器IP:8080` 不通。

## 5. 备份与异地复制

```bash
cp scripts/backup-db.sh /usr/local/bin/
chmod +x /usr/local/bin/backup-db.sh
echo '你的备份加密口令' > /etc/xyx/backup.pass
chmod 600 /etc/xyx/backup.pass

# 异地目标：rclone 配置好后填到这里（示例：阿里云 OSS 的某个 bucket 前缀）
cat > /etc/xyx/backup.env <<'EOF'
OFFSITE_REMOTE=oss:assoc-backup/daily
EOF
chmod 600 /etc/xyx/backup.env

# 每天 3 点
( crontab -l 2>/dev/null; echo "0 3 * * * . /etc/xyx/backup.env && /usr/local/bin/backup-db.sh >> /var/log/xyx/backup.log 2>&1" ) | crontab -
```

对象存储侧必须打开**版本控制**并设置**生命周期**（例如保留 90 天），否则本地删了、异地也留不住历史。

**验收**：手动跑一次 `/usr/local/bin/backup-db.sh`，`/var/backup` 里出现加密包，`rclone lsf oss:assoc-backup/daily` 能看到同名文件；在干净的临时目录按运维手册恢复一次。

## 6. 上线前最后一轮验收（逐条打勾）

- [ ] 匿名打开首页、竞赛档案、积分榜、公告、荣誉 —— 都是 200
- [ ] 匿名打开技术空间的站内文章 —— 被拦
- [ ] 超管首次登录 —— 被强制改密，改密后重新登录
- [ ] 超管建一个成员账号 —— 对方首次登录也被强制改密
- [ ] 生成邀请码，用 `/register` 注册 —— 成功
- [ ] 建一场比赛、记一个奖 —— 前台看得到，积分榜同步增加
- [ ] 登记一笔挖洞并审核 —— 榜上出现；同漏洞点第二笔达到 10 分后封顶
- [ ] 上传一张图 —— 前台看不到；审核时选“仅成员”，匿名看不到、登录成员能看到
- [ ] 提交一笔积分申诉 —— 后台能处理；重复处理被拒绝
- [ ] 招新表单提交 —— 后台能看到完整字段，能流转状态
- [ ] **换一个浏览器退出登录，确认后台进不去**
- [ ] 四种管理员角色分别登录 —— 只能看到自己职责范围内的菜单，越权 URL 返回 403
- [ ] 手机 4G 打开域名 —— 能开（证明不是只在内网通）

## 7. 迁移与回滚

- Flyway 迁移只做**加法**：新表、新列、新索引；不在迁移里改历史数据语义。
- 发布前 `deploy.sh` 会强制备份数据库；备份失败就不发布。
- 回滚旧 JAR 前先确认：新版本迁移是否向后兼容。新增列均有默认值/可空，旧 JAR 可以继续跑；如果某次迁移删列或改类型，必须先把备份恢复到新库再回滚。
- 每季度做一次「迁移后回滚演练」：在测试库执行新版本一次、切回上一个 JAR、确认登录/积分求和/图片访问/审核状态正常，并在运维手册记录。

## 已知的坑（都在部署时遇到过或预判过）

| 坑 | 处理 |
|---|---|
| 80/443 打不开 | 域名没备案，或云安全组没放行 |
| 应用起不来 | 先看 journalctl；多半是 DB_PASSWORD 没设、ADMIN_PASSWORD 太弱或 Flyway 校验失败 |
| `ADMIN_PASSWORD 不符合安全要求` | 换 12 位以上、三类字符以上的密码；首次登录会强制改密 |
| 备份脚本报缺 my.cnf | 按 2.1 创建 `/etc/xyx/my.cnf`，chmod 600 |
| 备份只在本机 | 没设置 `OFFSITE_REMOTE` 或没装 rclone |
| 上传图片 403 | `/srv/xyx` 权限不对，要给 xyx 用户 |
| 上传 1MB 就被拒 | 确认用的是新版本（multipart 已配置 10MB），并检查 Nginx `client_max_body_size` |
| 内存被吃光 | 确认 MemoryMax 生效；`-Xmx768m` 不能再大 |
