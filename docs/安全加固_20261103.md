# 安全加固记录（2026-11-03）

依据《CUST-20261103 渗透测试报告》，本轮处理以下问题。

| 编号 | 处理结果 | 说明 |
|---|---|---|
| F-01 | 已修复 | 同一 IP + 用户仅冷却 60 秒；同一 IP 15 分钟内失败 30 次后阻断该 IP |
| F-02 | 已加固 | 默认只监听回环地址，只信任本机 Nginx 注入的转发头 |
| F-03 | 已加固 | Actuator 仍只暴露 health、不显示详情 |
| F-04 | 已修复 | 参数格式错误返回 400，不支持的方法返回 405 |
| F-05 | 已修复 | 登录成功、失败、冷却、IP 阻断和登出均写入认证审计 |

## 登录限流

- 以前同一 IP + 用户失败 5 次后会锁定 15 分钟，报告中的“IP + 用户”建议其实已经是原实现。
- 现在不再对账号做跨 IP 的长期硬锁定。
- 同一 IP + 用户失败 5 次后冷却 60 秒。
- 同一来源 IP 在 15 分钟内失败 30 次后，整个来源 IP 被阻断到时间窗结束。
- 认证错误页面使用统一文案，不区分账号不存在、密码错误或来源被限流。

## 认证审计

使用现有 `audit_log` 表记录：

- `AUTH_LOGIN_SUCCESS`
- `AUTH_LOGIN_FAILURE`
- `AUTH_LOGIN_COOLDOWN`
- `AUTH_LOGIN_BLOCKED`
- `AUTH_LOGOUT`

审计只保存尝试的用户名、IP、请求 ID、动作和说明，不保存密码。审计写入失败只记录应用日志，不阻断登录或登出。

## 部署要求

- `SERVER_ADDRESS` 默认为 `127.0.0.1`。
- Nginx 与应用同机部署时保持默认值。
- Nginx 必须覆盖 `X-Forwarded-For`，并使用 `$remote_addr`。
- 如果反向代理与应用分离部署，必须通过防火墙只允许代理来源访问应用端口。
- `/actuator` 不得在公网开放。
